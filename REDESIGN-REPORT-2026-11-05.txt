FLIGHT RECORDS AND MANUAL PROCESSING — CURRENT BEHAVIOR
Flight date/time is stored metadata only. There are no countdowns, automatic time-based parcel transitions, or handover restrictions based on the recorded departure date/time.
Staff explicitly save a flight plan, confirm actual carrier handover, receive parcels at the destination and confirm customer collection. Existing branch authorization, parcel eligibility, transaction boundaries, duplicate protection and balance-settlement rules remain enforced.
On a flight record, the responsible origin branch can open Edit recorded flight time and save a past or future date/time. Authorized admins can edit a legacy record with no branch route. The input uses the origin branch timezone. The date and time metadata are kept consistent; handover timestamps, parcel states and payment records are preserved.
Metadata edits use a transaction, locked dispatch row, server validation, an audit entry retaining before/after values and a stale-form check to prevent overwriting a concurrent time edit. Editing is supported before and after handover.
The flight page and printable manifest retain full parcel data; selection uses readable item/customer/weight/photo cards. Currency and weight-unit totals stay separate. The booking date label reads Parcel received date for branch bookings.

FLIGHT HISTORY VIEW

Each recorded trip shows its recorded date/time, flight number, carrier, route, actual handover date/time and staff recorder, parcel count and identifiable parcel previews. Planned trips are explicitly labeled not handed over; actual carriage is based on the recorded handover, never the flight clock. Flight date filters use the stored local flight date, with actual handover shown separately.
Search supports flight/carrier/reference, parcel number/description, historical sender name and recipient name. Optional date range and handover-status filters, clear/reset, pagination, full-flight links and print-manifest links are available.
Previews are bounded to three parcels per trip with an explicit partial-list message; View flight and all parcels opens the full existing record and every assigned parcel. This avoids loading all parcels from every flight into one history page. Records remain scoped to the employee's existing readable branches.
